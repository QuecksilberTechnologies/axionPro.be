# Tenant Policy Name Uniqueness — 2026-10-09

## Environment and build

- Source: local backend workspace on 2026-10-09.
- Live read-only verification: localhost Angular consumer backed by the deployed Render API.
- Database mutation: local PostgreSQL `axionpro_local_october_2026` only.
- Render API and Render database deployment: not performed.

## Scenario and expected result

One Policy identity owns its numbered versions. The same Policy cannot contain two version 1 rows
because `(PolicyId, VersionNumber)` is already unique. Two separate active Policy identities in the
same tenant must not use the same trimmed, case-insensitive name. Create, Draft update and bulk
preview must return an actionable duplicate-name message directing the user to the existing Policy
and its next version.

## Evidence and actual result

- The deployed TechNova list exposed 14 Policy identities and no repeated displayed Policy name.
- `PolicyVersion` retains its unique `(PolicyId, VersionNumber)` model index.
- Create and Draft-update repository paths compare normalized Policy names within the tenant and
  return the documented Conflict message.
- Bulk Policy Definition preview reports the same conflict when a different PolicyCode reuses an
  existing Policy name.
- `EnforceTenantPolicyUniqueName.sql` aborts if historical duplicates exist, then creates the
  partial normalized unique index `UX_Policy_Tenant_NormalizedName`.
- The migration ran successfully against the local PostgreSQL database and the index was queried
  back by name.
